# teuilor — конструктор на GitHub Pages

Полностью статический сайт: выбор деталей, послойная сборка фигурки, пересчёт цены и коллекция в браузере. Каталог общий для всех посетителей, собирается из папок репозитория. Сервер приложения, база данных и платное хранилище не нужны. При публичном репозитории GitHub Pages доступен на бесплатном тарифе в пределах лимитов GitHub.

## Публикация

1. Добавьте файлы проекта в ветку `main` на GitHub.
2. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. В **Actions → Publish GitHub Pages** дождитесь успешной публикации. Если настройки Pages включены уже после последнего коммита, нажмите **Run workflow**.
4. Адрес сайта покажут Settings → Pages и результат deployment. Для репозитория `IgorTrubnikov/lego` стандартный адрес — `https://igortrubnikov.github.io/lego/`.

Workflow автоматически тестирует проект, собирает каталог и публикует `_site/` при каждом push в `main`. Node.js нужен только при сборке в Actions и для локальной разработки; опубликованный сайт состоит из HTML/CSS/JS и изображений. Все пути относительные: сайт работает и в `/lego/`, и на собственном домене.

## Информация для посетителей

Кроме конструктора, при сборке создаются четыре самостоятельные статические страницы:

- `works.html` — галерея готовых работ с реальными фотографиями.
- `contacts.html` — Telegram, Instagram и TikTok с предоставленными ссылками.
- `delivery.html` — оплата через Авито или Озон-сделку, доставка по России и СНГ: СДЭК, Авито, Яндекс Доставка, Озон Доставка, постаматы и другие сервисы.
- `faq.html` — стоимость, срочная сборка и пять шагов заказа.

Общий заголовок, подвал и тексты информационных страниц находятся в `scripts/site-pages.mjs`; галерея формируется в `scripts/gallery.mjs`. Главная редактируется в `index.html`; маркеры `SITE_HEADER` и `SITE_FOOTER` заменяются при сборке общей навигацией. На телефоне меню раскрывается без JavaScript. Адреса относительные и работают на GitHub Pages под `/lego/`.

На главной размещены предоставленные показатели мастерской: 250+ отзывов, 300 рамок и ручная сборка за 1–3 дня. Этот срок единообразно указан во всех разделах; срочная сборка день в день требует предварительного согласования и доплаты. Кнопки заявки открывают Telegram: сайт не принимает оплату и не создаёт заказ автоматически. Итоговую стоимость рамки, способ оплаты и доставки согласовывают в переписке.

## Галерея готовых работ

Страница `works.html` содержит настоящие фотографии мастерской: рамки, брелоки и композиции под колпаком. Есть фильтры, увеличение, переключение стрелками и клавишами ←/→, закрытие по Escape и восстановление фокуса. Без JavaScript все фото остаются доступными по прямым ссылкам. На главной показаны три примера со ссылкой на галерею.

Данные: `assets/gallery/works.json`. У каждой записи есть постоянный `id`, исходное имя, категория (`frames`, `keychains`, `domes`), название и описательный `alt`. В `thumbs/` лежат уменьшенные WebP (длинная сторона до 720 px), в `full/` — большие версии (до 1800 px). Фотографии не обрезаются и не перерисовываются. Ориентация сохранена, служебные метаданные удалены из веб-копий. Оригинальные фотографии в репозиторий и на сайт не включены.

Для добавления фото:

1. Добавьте запись с новым `id`, `source`, `category`, `title` и `alt` в `works.json`.
2. Положите исходник с точным именем `source` в локальную папку.
3. Выполните `node scripts/import-gallery.mjs /путь/к/исходникам` (требуется ImageMagick с поддержкой HEIC). Поддерживаются и обычные JPEG/PNG. Уже подготовленные фото без исходника в этой папке остаются нетронутыми.
4. Проверьте `npm run build`, затем добавьте новые WebP и обновлённый JSON в GitHub.

Альтернатива без конвертера: самостоятельно подготовьте два WebP, положите их в `assets/gallery/thumbs/<id>.webp` и `assets/gallery/full/<id>.webp` и укажите их пути и размеры (`width`, `height`, `fullWidth`, `fullHeight`) в JSON. Сборка GitHub Pages использует уже готовые файлы и не требует HEIC-декодера. Для удаления работы удалите её запись и соответствующие два WebP. Пустой список `[]` допустим: галерея покажет сообщение об обновлении, а примеры старых фото исчезнут с главной. Текущая коллекция содержит 28 фотографий: 15 рамок, 9 фото брелоков и 4 композиции под колпаком. Соответствие нумерации исходников, категорий и контрольных сумм сохранено в `scripts/gallery-replacement-plan.json`.

## Как добавить новую деталь без правки кода

Папки в корне репозитория:

| Папка | Содержимое |
| --- | --- |
| `haircuts/` | Причёски |
| `faces/` | Голова целиком вместе с лицом |
| `clothes/` | Торс с руками и кистями |
| `pants/` | Брюки со ступнями |
| `accessories/` | Аксессуары слева от человечка |
| `animals/` | Животные справа от человечка |
| `altars/` | Свадебные алтари, качели и балкон |

Пример имени файла:

```text
haircuts/kare__250__Каштановое каре.png
```

Формат: **`идентификатор__цена__Название.png`** — два подчёркивания между полями.

- Идентификатор `none` зарезервирован для пустого выбора в аксессуарах, животных и свадебных композициях.
- Идентификатор: латинские буквы, цифры, дефисы (`kare`, `brown-curls`). Уникальный внутри категории. Сохраняйте его при изменении названия или цены, чтобы выбор посетителя не сбрасывался.
- Цена: целое число 0–100000, без символа валюты, в рублях.
- Название: 1–45 символов; допустимы русский текст и пробелы.
- PNG/WebP с прозрачностью, **600 × 720 px**, до 2 МБ. Поддерживается также SVG с `viewBox="0 0 600 720"`; демонстрационные детали уже лежат в папках в этом формате.

На GitHub откройте нужную папку → **Add file → Upload files**, перетащите изображения → **Commit changes** в `main` (или PR с последующим merge). Публикация запустится автоматически. После успешного выполнения Actions новые варианты станут доступны всем; открытый сайт нужно обновить.

Для изменения цены или названия переименуйте файл, сохранив идентификатор. Для удаления — удалите файл. В каждой из четырёх основных категорий должна оставаться хотя бы одна деталь. Аксессуары, животные и свадебные композиции необязательны: эти папки можно оставить пустыми или удалить. Варианты «Без аксессуара», «Без животного» и «Без композиции» с ценой 0 ₽ сайт добавляет автоматически. Готовые варианты можно заменять своими изображениями по тому же шаблону. Если цена, формат имени, размер холста или идентификатор неверны, сборка завершится с понятной ошибкой в Actions; предыдущая опубликованная версия останется доступной.

Не нужно вести JSON вручную: `scripts/build.mjs` создаёт `_site/catalog.js` автоматически. Браузер не умеет читать список файлов GitHub Pages, поэтому этот шаг выполняется при публикации. GitHub-токен не помещается в код сайта; загрузки на сайт нет, управление файлами доступно через ваш вход в GitHub.

## Аксессуары из каталога

В `accessories/` находятся 47 вариантов, подготовленных по предоставленному каталогу. Отдельно представлены два цвета ноутбука, два размера колёс и пять цветов стержней. Все аксессуары, включая игрушечных мишек и кроликов с этого листа, стоят 200 ₽. Для изменения цены достаточно переименовать файл по общему шаблону. Пробные аксессуары удалены; недоступный аксессуар в сохранённой фигурке сбрасывается на «Без аксессуара», а в сохранённой коллекции удаляется вместе со своей доплатой. Остальные детали коллекции сохраняются.

Это иллюстрации по референсу на прозрачном холсте 600 × 720 px, расположенные в области аксессуара слева от фигурки. SVG содержит самостоятельное WebP-изображение. Атрибут `data-preview-box="x y width height"` на корневом SVG задаёт тесную область для карточки выбора: сборка проверяет её границы, а сама фигурка использует полный холст. Это позволяет одинаково хорошо рассмотреть тонкую палочку и широкий геймпад.

Повторная подготовка из трёх прозрачных квадратных листов 4 × 4 (порядок и размеры перечислены в скрипте):

```sh
node scripts/prepare-accessory-assets.mjs sheet-1.png sheet-2.png sheet-3.png
```

Скрипт требует ImageMagick 7 и заменяет содержимое папки аксессуаров только после успешной подготовки всех 47 файлов. Он не участвует в сборке сайта. Крупные исходные листы в публикацию не включены.

## Свадебные композиции

Раздел «Алтари» содержит шесть вариантов из предоставленного референса: «Алтарь 1», «Алтарь 2», «Алтарь 3», «Алтарь 4», «Качели» и «Балкон». Начальная доплата за каждый — 400 ₽; цена меняется в имени файла в `altars/`. Пустой вариант «Без композиции» бесплатный. Композиция выбирается независимо от аксессуара и животного, участвует в итоговой цене, случайном выборе, сбросе и сохранении в коллекцию. Старые сохранённые фигурки открываются без композиции.

Это отдельные прозрачные иллюстрации архитектуры без встроенных персонажей. В полном предпросмотре композиция находится позади выбранного персонажа, а все детали персонажа вместе уменьшаются до 60% и смещаются на (120, 260) на общем холсте 600 × 720 px. Без композиции масштаб прежний. В карточке выбора показана только архитектура. Для своих композиций используйте прозрачный холст 600 × 720 px; область архитектуры x=20–580, основание на y=700, центральный проход свободен для персонажа. Слой композиции находится перед остальными слоями в SVG, поэтому рисуется позади них.

Повторный импорт из подготовленного прозрачного листа 1536 × 1024 px, сетка 3 × 2 в указанном выше порядке:

```sh
node scripts/prepare-wedding-assets.mjs wedding-sheet.png
```

Требуется ImageMagick 7. Скрипт нарезает готовое изображение и выравнивает шесть файлов; он не используется при сборке GitHub Pages. Исходные листы в сайт не включены.

## Объёмная коллекция по фотореференсам

В каталог добавлены изображения пластиковых деталей, подготовленные по предоставленным фотографиям: 6 вариантов торсов (светлый пиджак, чёрный костюм, жакет с котёнком, красная куртка, тропическая рубашка, футболка с единорогом), 6 цветов ног и 6 животных (далматинец, рыжий и белый котята, овчарка, лабрадор, французский бульдог). Это новые иллюстрации по референсам, а не точные вырезки с исходных фотографий. Все изображения уже нормализованы на прозрачный холст 600 × 720 px.

Файлы этой коллекции имеют идентификаторы с префиксом `3d-` и пометку «Новое» в каталоге. Это объёмные 2D-рендеры: сайт по-прежнему статический, без 3D-движка и платных API. Первоначальные 34 варианта также перерисованы в глянцевом пластиковом стиле, с сохранением дизайнов, названий, цен и идентификаторов. Для первого посещения/сброса выбран новый светлый пиджак и молочные ноги; сохранённый выбор посетителя не заменяется. Цены в именах новых файлов — демонстрационные, их можно изменить обычным переименованием перед приёмом реальных заказов.

Для повторного импорта подготовленных изображений доступен вспомогательный скрипт:

```sh
node scripts/prepare-studio-assets.mjs torsos.png legs.png animals.png
```

Он требует ImageMagick 7 и три прозрачных листа 1536 × 1024 px с сеткой 3 × 2, в порядке, указанном в скрипте. Скрипт только разрезает и позиционирует готовые изображения. Для обычного добавления файлов, сборки и публикации он не нужен. Исходные референсы и большие листы не включены в публикацию; 18 готовых WebP занимают вместе менее 1 МБ.

### Перерисовка первоначального каталога

Первоначально были обновлены 34 фрагмента: 6 причёсок, 6 голов, 6 торсов, 6 брюк, 5 аксессуаров и 5 животных. Для оставшихся в каталоге вариантов прежние SVG-адреса сохранены; внутри SVG находится самостоятельное изображение WebP на прозрачном холсте. Пять пробных аксессуаров заменены новой коллекцией, описанной выше. Внешних ссылок внутри изображений нет. Поэтому старые сохранённые фигурки продолжают загружать детали по прежним URL, а каталог не содержит дубликатов вариантов.

Для причёсок сохранён общий контур свободной области лица: длинные пряди находятся по бокам, глаза и рот остаются открытыми. Результаты проверяются браузерными тестами вместе с прозрачностью и положением остальных деталей. Снимок идентификаторов, цен, названий и URL до перерисовки хранится в `test/fixtures/legacy-catalog.json` для проверки совместимости.

Повторный импорт подготовленных листов (ImageMagick 7, прозрачные листы 1536 × 1024 px, сетка 3 × 2):

```sh
node scripts/redraw-legacy-assets.mjs hair.png faces.png clothes.png pants.png accessories.png pets.png
```

Порядок вариантов на каждом листе задан в скрипте. Последняя ячейка на листах аксессуаров и животных пустая. Этот инструмент не участвует в сборке GitHub Pages; обычное добавление PNG/WebP/SVG в папки остаётся прежним. Большие исходные листы не включены в сайт.

## Требования к изображениям

Все детали используют **полный холст**, а не обрезку по границам объекта. [Шаблон](assets/part-template.svg) задаёт положение головы, торса и ног. Импортируйте его в графический редактор как направляющие и удалите перед экспортом. Непрозрачный фон перекроет другие детали: прозрачность нужно проверить в редакторе. Сборка проверяет размеры и заголовок формата, но не художественное качество и прозрачность изображения.

- Голова: x=224–376, y=190–320; штифт x=271–329, y=173–195.
- Причёска: примерно x=195–405, y=90–315, поверх головы.
- Торс: верх примерно x=234–366, y=326, низ x=204–396, y=505. Включает обе руки и кисти. Общий диапазон для объёмной коллекции x=139–461, y=285–542; шея перекрывается головой. Старые иллюстрации также совместимы.
- Брюки: x=212–388, y=451–683 для объёмной коллекции; крепёжные штифты в верхней части перекрываются торсом, пояс начинается около y=505. Старые иллюстрации без штифтов начинаются около y=498.
- Аксессуары: область слева, x=15–165, y=405–695.
- Животные: область справа, x=430–600, y=435–700.
- Для новых категорий используйте [шаблон аксессуаров и животных](assets/extras-template.svg). Холст такой же: 600 × 720 px. Предмет или животное уже должны располагаться в своей области на полном прозрачном холсте; сайт не переносит их автоматически. Все варианты в каталоге используют общий объёмный пластиковый стиль. Одновременно можно выбрать один аксессуар, одно животное и одну свадебную композицию; их цены прибавляются к цене фигурки.
- Порядок слоёв: брюки → торс → голова → причёска → аксессуар → животное. Соединения слегка перекрываются. Для длинных причёсок, которые должны уходить за торс, понадобится отдельный задний слой в следующей версии.

Единые фронтальный ракурс, масштаб, освещение, материал и цвет кожи обязательны для аккуратного совмещения. Произвольная фотография не выравнивается автоматически. Лучше готовить детали из одной 3D-сцены или системы иллюстраций. Текущая версия использует 2D-слои, без вращения фигурки.

## Локальная разработка

Node.js 18+. Для запуска и сборки внешние зависимости не нужны:

```sh
npm test
npm start
```

`npm start` собирает `_site/` и запускает локальный сервер на порту 3000 (`PORT` для переопределения). После изменения файлов перезапустите команду или выполните `npm run build` и обновите страницу. `npm run build` создаёт готовую статическую папку, её можно разместить на любом статическом хостинге. `_site/` не нужно коммитить.

### Браузерные проверки

Требуется Node.js 20+ (в GitHub Actions используется 22).

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

Проверяются клики по всем вкладкам после выбора каждых брюк, клавиатурная навигация, цена и прозрачность причёсок над глазами, бровями и ртом. Проверки выполняются в настольном и мобильном размерах. Для установленного системного Chromium можно задать `CHROMIUM_PATH=/usr/bin/chromium`. Playwright используется только для тестов и не попадает в опубликованный сайт. GitHub Actions выполняет эти проверки перед публикацией.

## Что хранится у посетителя

Текущий выбор и коллекция сохраняются в localStorage браузера, а не в общем каталоге. Старые коллекции содержат снимок цены и ссылки на изображения на момент добавления: это не оформленные заказы. При удалении/переименовании файла изображения старые коллекции могут потерять его предпросмотр. Переименование цены или названия меняет URL изображения; для длительного хранения коллекций оставляйте старые файлы по прежним адресам либо добавьте отдельную систему неизменяемых URL.

Платёжной системы, отправки заказов и общей истории заказов пока нет. На GitHub Pages возможен бюджетный каталог-конфигуратор со сбором заявок через внешний сервис; полноценная обработка и проверка заказов потребует отдельного решения. Шрифты Google Fonts необязательны: при их недоступности используются системные.
